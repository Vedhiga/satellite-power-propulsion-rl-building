## 1. Classification Framework Enforcement

Every variable across all subsystem tables and parameter files has been classified into exactly one of the following seven canonical categories:

1. **`OBSERVED`**: Directly present as a physical sensor measurement or metadata value in the original source dataset.
2. **`DERIVED`**: Mathematically calculated strictly from observed source variables.
3. **`MODEL_PARAMETER`**: Physical parameter backed by authoritative manufacturer or aerospace standard documentation (e.g., SolAero Z4J+ solar cell specifications, BIRDS-3 1U mass limit).
4. **`MODEL_GENERATED`**: Data generated dynamically by the proposed simulation model during RL environment execution (0% present in EDA tables).
5. **`ASSUMPTION`**: Researcher-selected hypothetical baseline value reserved for building the integrated simulation environment.
6. **`COMMAND_CONTROL`**: Control command variables present in the source data (e.g., STFT `test_mode`, `ton`).
7. **`IDENTIFIER`**: Tracking labels, timestamps, filenames, or serial numbers.

## 2. Answers to the 12 Forensic Audit Questions

### Q1: Are all raw datasets preserved?
**YES.** All original downloaded archives (`8kp25ycf63-1.zip`, `archive (6).zip`, `archive (7).zip`) and extracted raw files under `projects/data/raw/` remain 100% unmodified.

### Q2: Are the three datasets still independent?
**YES.** The Power (BIRDS EPS), Orbit (CelesTrak Active Catalog), and Propulsion (STFT Hot-Fire Tests) datasets are stored in completely separate folders and files under `projects/data/processed/`. No cross-spacecraft joins, timestamp alignments, or row merging have been performed.

### Q3: Are synthetic propulsion test data clearly identified?
**YES.** The Spacecraft Thruster Firing Tests (STFT) dataset is explicitly identified as **physics-based synthetic hot-fire ground test data** generated by Patrick Fleith (2021) for algorithm benchmarking, NOT flight telemetry from an operational space mission.

### Q4: Are battery-capacity assumptions excluded from EDA?
**YES.** The nominal battery capacity ($2.6\text{ Ah}$) and Coulomb-counting `SOC_PROXY` have been completely removed from the observed power dataset (`power_subsystem.csv`). $2.6\text{ Ah}$ is isolated in Section B (`FUTURE SIMULATION ASSUMPTIONS`) of `subsystem_parameters.csv`. EDA utilizes only observed battery voltage, current, temperature, and panel telemetry.

### Q5: Are target-orbit assumptions excluded from EDA?
**YES.** The target orbit altitude ($400\text{ km}$), target inclination ($51.6^\circ$), and calculated `orbit_error` have been removed from `orbit_subsystem.csv`. They are isolated in Section B (`FUTURE SIMULATION ASSUMPTIONS`) of `subsystem_parameters.csv`. Orbit EDA utilizes only observed Keplerian elements from CelesTrak.

### Q6: Is spacecraft mass verified and resolved?
**YES.** The inconsistency between $12.0\text{ kg}$ and $1.33\text{ kg}$ was investigated:
* **$1.33\text{ kg}$** is the documented physical mass limit for BIRDS-3 1U CubeSats (NepaliSat-1, Raavana-1, Tsuru, Uguisu) per the 1U CubeSat Specification Standard (`MODEL_PARAMETER`).
* **$12.0\text{ kg}$** was a researcher-selected wet mass assumption for 6U/12U satellite thruster maneuvers (`ASSUMPTION`).
* The STFT ground test documentation does NOT specify a satellite mass.
* Neither value is forced across all subsystems in source-data EDA.

### Q7: Is Isp properly sourced and classified?
**YES.** Inspection of `STFT Dataset Description.pdf` confirmed that $225.0\text{ s}$ is **NOT** explicitly provided as a fixed constant in the STFT documentation. It has been removed from `MODEL_PARAMETER` and re-classified as `DERIVED / ASSUMPTION` ($I_{sp} = F / (\dot{m} \cdot g_0)$) for future simulation modeling.

### Q8: Are artificial propulsion profiles removed?
**YES.** All generated formulas (`0.4*p`, `160*p`), fake thruster IDs (`SN_NOMINAL_RCT`), and artificial test profiles (`CLEAN_NOMINAL`) have been purged from the processing pipeline.

### Q9: Are derived quantities explicitly labelled?
**YES.** All derived variables ($P_{\text{solar\_total\_W}}$, $P_{\text{battery\_W}}$, $P_{\text{load\_W}}$, semi-major axis $a$, perigee altitude $h_p$, apogee altitude $h_a$) are explicitly classified as `DERIVED` in `FINAL_DATA_PROVENANCE.csv`. Battery load power derivation ($P_{\text{load}} = P_{\text{solar}} + P_{\text{battery}}$) is unclipped (0 arbitrary clipping applied).

### Q10: Are model-generated quantities separated from source data?
**YES.** Zero model-generated or synthetic simulation variables exist in the clean subsystem tables for EDA.

### Q11: Are there any remaining unexplained/generated values?
**NO.** All 37 variables across all files have complete, traceable provenance recorded in `FINAL_DATA_PROVENANCE.csv`.

### Q12: Is the dataset ready for independent EDA?
**YES.** All integrity requirements are satisfied. The dataset is **READY FOR EDA**.
